# Recipes v0.1

Russian responsive catalog, published recipe pages, base-quantity servings scaling, nutrition coverage, and an anonymous shopping list.
Admin supports recipe create/edit, draft/publish/archive, ordered ingredients/groups/steps, ingredients/nutrition, and optional covers.
Public repository methods always constrain publication. Basket stores only versioned recipe IDs, servings and timestamps; the server resolves current published data in batches.

## Local verification

Use an isolated PostgreSQL 18 instance and set DATABASE_URL for the current process. Integration and E2E harnesses create and drop random databases; they never apply migrations to the source database. Missing prerequisites fail tests.
Run npm run test:integration, npm run test:e2e. E2E generates ephemeral credentials and images; no real admin credentials are used.
npm run db:seed-demo explicitly creates six original demo recipes and ten ingredients. Existing slugs are preserved, including owner edits. Seed is transactional and may be rerun.

## Limitations

One admin role, no signup/RBAC, local media, anonymous localStorage basket (50 recipes, 1–1000 servings), no slug redirects, no density conversion, no ratings/planning/prices.
Catalog shows up to 100 most recent published recipes; pagination is deferred. Quantity presentation rounds to at most six decimal places; canonical Decimal values are not changed.
Public catalog/recipe caching optimization is deferred until after first deployed manual review. Public routes use dynamic SSR.
An uploaded/replaced cover is retained; automated orphan-file garbage collection is deferred. Public media resolves only covers of published recipes.
Nutrition demo values are test data, not precision measurements. Incomplete nutrition never appears as a full total.
